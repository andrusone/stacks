# Stacks installer: install, update and check a stack on this VM with one command

**Serves:** workbench:OC20
**Tier:** homelab
**Status:** draft 2026-11-24 (architect), from the owner's Check in `workbench:outcomes/oc20-stack-installer.md`; MVP 1 only.

`setup-stacks.sh` is a thin Bash script that builds and runs one small Go program. The program lists, installs, updates and checks stacks on the VM it runs on. A stack is a folder in the stacks folder (`~/src/stacks/stacks` by default; `STACKS_DIR` overrides it) holding `stack.toml` and executable steps. The installer knows no stack by name. Everything in this spec is new: the older files in this repository (`compose/`, `health/`, `plex/`, `qbt/`, `docs/SPEC-stacks.md` and the rest) are reference only and are not copied, changed or extended. New code goes in `setup-stacks.sh`, `cmd/setup-stacks/`, `internal/installer/`, `internal/stack/`, `tests/` and `stacks/`.

## Requirements

| ID | P | Requirement | Acceptance |
|---|---|---|---|
| SI-FR-01 | MVP 1 | **Help lists the stacks and the flags.** `setup-stacks.sh --help` prints every stack in the folder one per line (name, then its `meaning`) and every flag, changes nothing and exits 0. With no stacks it says there are none and where a stack goes (the stacks folder path), and still lists the flags. | MVP 1: tests with an empty folder and with three test stacks; the stack lines are vertical. |
| SI-FR-02 | MVP 1 | **`stack.toml` is the one file that makes a stack exist** `(contract)`. Required fields: `name` (equals the folder name), `meaning`, `version`, `user`, `units` (list), `ports` (list of integers), `nas_paths` (list, may be empty) and `env` (list of keys, may be empty). A missing field, a wrong type or a parse error names the file and the line, and the stack is not usable. | MVP 1: a test per missing field, one wrong type, one parse error, and one name that differs from its folder. |
| SI-FR-03 | MVP 1 | **No flags, or an unknown stack, lists and stops.** With no flags it changes nothing, says no stack was named, shows the list of SI-FR-01 and exits non-zero. `--stack nosuch` says which name it did not know, shows the list (or says there are none) and exits non-zero. | MVP 1: tests for no flags and an unknown name, with and without stacks. |
| SI-FR-04 | MVP 1 | **Flags that conflict are an error, not a guess** `(contract)`. `--check` with `--apply`, `--stack` given twice, `--apply` with no `--stack`, and an unknown flag each print which flags conflict and ask to pick one, exit 2 and change nothing. | MVP 1: one test per case, asserting exit 2. |
| SI-FR-05 | MVP 1 | **The default is a dry run.** `--stack <name>` with no `--apply` prints one line per change it would make, each starting `would:` or `blocked:`, ends with `changes: n`, and changes nothing. A `blocked:` line says what is wrong and how to fix it; the `would:` lines are still listed. It exits non-zero when anything is blocked. | MVP 1: test stacks with and without a block. |
| SI-FR-06 | MVP 1 | **Problems stop the run before any change, and no secret is ever asked for.** Blocked cases: the stack's values are missing from `/etc/stacks/<name>.env` (it names the file and prints the stack's `example.env`); the `stacks` clone has uncommitted changes (says to commit or discard them); `/svr` is missing or is not a separate mount (it says so and never mounts or formats anything). With `--apply` a block stops the run before the first change. | MVP 1: a test for each case that asserts no change was made. |
| SI-FR-07 | MVP 1 | **`--apply` installs, and a rerun is safe.** In order: the checks, the run-as user (created as a system user with no login when missing), the four folders `data`, `logs`, `config` and `backup` under `/svr/<name>` (owned by the user, mode 750; a wrong owner or mode is corrected and counted), the stack's `install apply` step, its `check` step if it has one, and last the record in `/var/lib/stacks/<name>` (name, version, commit, ports, NAS paths, units). If any step fails no record is written. A rerun and the dry run after it both end `changes: 0`. A recorded version that differs from the stack's is an update: the dry run says `would: update <name> from vX to vY` and `--apply` does it. | MVP 1: runs on a test VM, as in the outcome's Try it (the program's own tests use a temporary root for the pieces that need no root). |
| SI-FR-08 | MVP 1 | **`--check` finds and checks what is installed** `(contract)`. For each installed stack it prints `ok`, `not ok` with what is wrong and the one command that fixes it, or `orphaned` (installed, no folder in the stacks folder). `ok` means the record is there, the version matches, each unit is enabled and active, the four folders exist and the stack's `check` step passes. A missing step (`check`, health, backup, restore) gives one `not yet:` line naming it. It names anything under `/svr/` that is not a stack's folder (`lost+found` ignored). Nothing installed says so and exits 0; it exits non-zero only when a stack is `not ok`. `--check --stack <name>` checks one stack and says so if it is not installed. It changes nothing. | MVP 1: tests over a fake record and fake units. |
| SI-FR-09 | MVP 1 | **A stack touches only its own things.** Installing one stack leaves every other installed stack `ok`. When the named stack wants a port or a NAS path that another installed stack's record holds, the dry run names both stacks and blocks. Stacks only in the folder are never compared, and a stack is never compared with its own record. | MVP 1: tests for a port clash, a NAS clash, and no clash with itself. |
| SI-FR-10 | MVP 1 | **It runs as the normal user, on the one OS it supports, one at a time** `(contract)`. Run as root it stops with one line. On anything but Ubuntu 26.04 it stops before any change with one plain line. A second run while one is running stops with one line. It calls `sudo` itself. | MVP 1: tests for root, another OS (through an os-release override the test sets) and a held lock. |
| SI-FR-11 | MVP 1 | **It works with no stacks and with many, and names none.** With an empty folder, SI-FR-01, 03, 05 and 08 behave as written. With three test stacks, adding one to the folder or deleting one changes nothing but that folder. No stack name appears in `setup-stacks.sh` or the Go program. The test stacks are generated from one template under `tests/`, not kept as three copies. | MVP 1: a test greps the program and script for the generated names; the generator is run by `mise run check`. |
| SI-NFR-01 | MVP 1 | **Small and plain.** Go standard library plus one TOML package; `go.mod` pins versions; every Go file at most 300 lines; `setup-stacks.sh` at most 150 lines; `mise run check` runs `go vet`, `go test ./...` and shellcheck on every new `*.sh`. | MVP 1: `mise run check` is green. |

## Homelab scope

Safe shortcuts for a two-person homelab: no service, no database, no uninstall (rebuild the VM instead), no retention, no cleanup of files an older version left behind, the standard image's passwordless sudo is assumed, Ubuntu 26.04 only, tests run against generated stacks and a temporary root, never the real `/svr` or `/etc`. Never skipped: the dry run is the default, nothing changes before a block is cleared, a rerun changes nothing, a secret is never typed into the script or stored in git, and the script never mounts or formats a disk.

## Boundaries

Owns: this repository's installer (`setup-stacks.sh`, the Go program, the contract in `docs/SPEC-installer.md`) and the folder `/var/lib/stacks`. Needs: the machine already set up by `machine` `setup.sh --profile server` (Go, git, sudo) hard; `/svr` mounted by the standard image hard. Never needs: Docker, compose, another stack running, the `network` repository at run time. Needed by: every stack, as the way it is installed. Backup: the repository on GitHub; a lost VM is recovered by cloning `stacks` and running `setup-stacks.sh --stack <name> --apply`.
